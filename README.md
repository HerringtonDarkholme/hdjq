# gojq-hd

A file-by-file port of [gojq](https://github.com/itchyny/gojq) v0.12.20 to
hd-lang. It keeps gojq's architecture (yacc parser tables, bytecode compiler,
backtracking VM with forks, scopes and path tracking, the allocator for
in-place updates, builtins generated from `builtin.jq`) and its algorithms,
and it adds nothing gojq lacks. YAML input and output are left out; compare it
with a gojq built without YAML.

## Layout

| gojq | gojq-hd |
| --- | --- |
| `lexer.go`, `parser.go` (goyacc tables) | `src/gojq/lexer.hd`, `parser.hd`, `parser_tables.hd` |
| `query.go`, `term_type.go`, `operator.go` | `src/gojq/query.hd`, `operator.hd` |
| `builtin.go` (generated from `builtin.jq`) | `src/gojq/builtin.hd` (generated by `tools/gen_builtin.py`) |
| `compiler.go`, `option.go` | `src/gojq/compiler.hd` |
| `code.go`, `env.go`, `execute.go`, `stack.go`, `iter.go` | `src/gojq/code.hd`, `env.hd`, `stack.hd`, `iter.hd` |
| `func.go` | `src/gojq/func.hd` |
| `encoder.go`, `preview.go`, `type.go`, `compare.go`, `number.go`, `error.go` | same names under `src/gojq/` |
| `module_loader.go` | `src/gojq/module_loader.hd` |
| `cli/*.go` (without YAML) | `src/cli/*.hd` |
| `cmd/gojq/main.go` | `src/main.hd` |

## Where the port differs, and why

- **Callbacks are closures, as in Go.** `argFunc0`..`3`, `mathFunc` and the
  compiler's `funcBuiltins`, `funcMatch` and `funcBreak` build closures that
  `opcall` operands hold. Four of Go's closures cannot be plain hd closures,
  since they read input or reach the host: `input`, `modulemeta`, `now` and
  the functions given with `WithFunction`. They are `Callback` variants,
  which the VM calls through its waiting `next!`.
- **Go's `lazy`/`defer` patching** of reserved code slots is an explicit
  reserve-then-patch, applied at the same point Go's defer runs.
- **Slices and maps are reference types in Go.** gojq relies on that for
  path tracking (`pathIntact` compares addresses) and for the allocator. So
  arrays and objects are boxes here, and an allocator tags the boxes it made.
  `v[0:len(v)]` keeps the box, since Go's slice keeps the address, and two
  empty arrays count as the same, since Go allocates every empty slice at
  `runtime.zerobase`. `opappend`
  copies the shared constant `[]` on its first append, as Go's append
  allocates.
- **Waiting.** Reading input and loading modules wait in hd (`!` functions).
  The VM loop stays a plain function. An `opcall` of `input`, `modulemeta`
  or `now` leaves the loop to `next!`, which does the I/O and resumes at the
  call. gojq's VM is resumable the same way.
- **Input is read whole** when an iterator first needs it, since hd has no
  streaming reader. The error snippets of invalid JSON still match gojq: the
  decoder replays Go's read-buffer growth (512 bytes, then 2x+512) and the
  CLI's 16 KiB tee buffer, so an error shows the same cut of the input.
- **`time.Local`** is a package variable, as in Go, loaded from `TZ` /
  `/etc/localtime` (TZif v1 data). Go loads it on first use; loading reads a
  file, which needs a waiting call in hd, so the CLI loads it before
  compiling.
- **isatty**: hd cannot tell (hd-lang #2382), so stdout counts as not a
  terminal: no color unless `-C`.
- **Invalid UTF-8.** A Go string may hold bytes that are not UTF-8 (from
  `@base64d`, `@urid`, raw input, `--rawfile`); hd strings may not. The port
  keeps each such byte b as the private-use character U+10FE00+b. Where Go
  exposes the byte, the port undoes it:
  - `utf8bytelength`, `@base64` and `@uri` give the byte back
  - `explode`, regexps and `strings.Map` see U+FFFD
  - both encoders print `\ufffd`
  - raw output (`-r`, `-j`, `stderr`, error messages, `halt_error`) writes the byte itself, through the file API to `/dev/stdout` or `/dev/stderr`, since the console writes only text (hd-lang #2410)

  One divergence remains: a genuine character from U+10FE80 to U+10FEFF is
  taken for such a byte. Every code point is a legal character, so no
  encoding inside a valid-UTF-8 string avoids this. Only a string value that
  holds bytes, as Go's does, would.
- **Stdin** is read as `/dev/stdin` bytes, since `read_all!` rewrites `\r\n`
  (hd-lang #2398); `read_all!` is the fallback.
- **`$ORIGIN` module paths** are skipped, as Go skips them when
  `os.Executable` fails; a Wasm program has no executable path.

## Testing

```sh
hd build --release
python3 conformance/run.py            # gojq's cli/test.yaml cases
GOJQ_CMD=/path/to/gojq python3 conformance/run.py   # the same suite on a gojq binary
```

The compiler is checked instruction by instruction against gojq's own: built
with `-tags gojq_debug`, gojq prints its bytecode under `GOJQ_DEBUG=stdout`,
and so does gojq-hd. For the 700 distinct queries of the suite, the listings
are identical (35,723 instructions):

```sh
GOJQ_DEBUG_BIN=/path/to/gojq-debug python3 tools/diff_bytecode.py tools/suite_queries.txt
```

`conformance/gojq-cli-tests.json` is gojq's `cli/test.yaml`, converted to
JSON (MIT, see `conformance/GOJQ-LICENSE`). gojq's test harness sets
`time.Local` to a fixed zone 7 hours behind UTC; the runner gets the same
from `TZ=Etc/GMT+7`.


## Results (darwin/arm64, against gojq 0.12.20 built without YAML)

Conformance: 885/909 of gojq's CLI suite, the same as gojq built without
YAML. The 24 that fail are the YAML cases in both. Every suite query, run on
six inputs, gives the same stdout, stderr and exit code as gojq: 3906 of 3906.
